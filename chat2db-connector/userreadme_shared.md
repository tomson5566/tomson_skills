# Chat2DB Connector 使用说明（共享密钥版）

> ⚠️ **阅读本文件前请先看这里**
>
> 这个版本是"**省事模式**"：所有人共用同一把 SSH 私钥，谁拿到都能连。
>
> 优点：同事**真的零操作**，双击就能用。
> 缺点：私钥一旦泄露，服务器就裸奔；且没法单独撤销某个人。
>
> 如果你的使用场景是 **3 人以内 + 用几周就结束**，可以选这个。
> 否则请回到 **userreadme.md**（每人独立密钥版）。

---

## 第 1 步：拿到压缩包

管理员会发给你一个 zip，名字类似 `Chat2DB-共享版.zip`。**解压**到任意文件夹（建议桌面），会得到这两个东西：

```
Chat2DB-共享版/
├── Chat2DBConnector.exe
├── id_ed25519
└── 这份说明.md
```

---

## 第 2 步：双击 Chat2DBConnector.exe

程序打开后，**只需要填一项**：点 **Browse…** 选 `id_ed25519`（就在 exe 旁边）。其他字段都是默认填好的。

填完点 **Save config** → **Connect**。

浏览器自动弹出来 = 成功了 ✅。

用完关窗口。

---

## ⚠️ 几个绝对不要做的事

| 不要做 | 原因 |
|---|---|
| ❌ 把这个 zip 发到群里/公开网盘 | 任何人都能登服务器 |
| ❌ 把 `id_ed25519` 复制到其他文件夹/同步到云盘 | 容易泄露 |
| ❌ 离职前不清电脑 | 下一任主人能用你的密钥登服务器 |
| ❌ 用同一把私钥连其他 SSH 服务 | 一处泄露，全盘皆失 |

---

## 怎么撤掉某个人的权限

共享密钥模式下，**没办法单独撤掉一个人**。要撤就只能全员重做：

1. 管理员重新生成一对新密钥
2. 把新公钥加到服务器，旧公钥从 `authorized_keys` 删掉
3. 重新打包新 zip 发给所有人

所以这个方案适合"团队稳定 + 短期"。

## 常见问题

### 🔴 弹窗 "Key file not found"

`id_ed25519` 不在 exe 旁边。**要么把 exe 和私钥放同一个文件夹**，要么 **Browse…** 手动选。

### 🔴 杀毒软件杀掉了 `id_ed25519`

有些杀软会主动"保护"私钥文件，删掉或者隔离。处理：

- Windows Defender：威胁防护 → 允许的威胁 → 添加 `id_ed25519`
- 其他杀软：找到"信任区" / "白名单" → 加这个文件

### 🔴 怎么知道是不是已经有人在用这个密钥

服务器上跑：

```bash
# 看 vscode 用户的 authorized_keys 里有几行
wc -l ~/.ssh/authorized_keys
# 看是谁连过来的（需服务器开 ssh 日志）
grep "Accepted publickey for vscode" /var/log/auth.log | tail
```

---

## 完全卸载

1. 删除解压出来的整个文件夹
2. 删除 `C:\Users\你的名字\.chat2db-connector\` 配置目录
3. 强烈建议通知管理员把 `authorized_keys` 里你那行公钥删掉（因为是共享密钥，删掉等于封死所有人）
