# 数据中台开发技能（Data Platform Dev）

## 触发场景

- 用户要**从零搭建**数据中台的分层表、命名规范、公共维度/事实表。
- 用户要**开发一段加工 SQL**（清洗、建模、汇总、增量合并），需要符合规范且可重跑。
- 用户要**配置数据同步/集成任务**、做字段映射与类型对齐、管理增量水位。
- 用户要**设计数据服务接口**、统一出参结构、错误码与鉴权。
- 用户要**配置数据质量规则、对账、监控告警**、调度依赖、补数重跑。
- 用户要**按规范化清单做评审 / 验收 / 上线检查**。
- 用户要把项目**迁移到新平台**或**新增一种方言 / 业务域 / 来源系统**。

> 本技能只处理"数据开发"范畴，不代替具体的数仓平台、调度系统、数据资产平台的操作。

## 核心设计原则（迁移与扩展的根基）

1. **平台无关**：正文规范与 SQL 例统一以 Hive / Spark SQL 为准；平台差异（方言）全部收敛在 `config/dialect.md`，正文不使用平台特有语法。
2. **原则通用**：分层模型、命名、建模、幂等、质量、安全、验收等原则适用于绝大多数关系型 / 数仓 / 湖仓技术栈。
3. **配置驱动扩展**：业务域、来源系统、刷新周期、增量标识、生命周期等编码一律来自 `config/` 下的编码表。企业定制 = 改配置，不重写规范。
4. **业务日期参数化**：业务 SQL 禁止出现实时日期函数与硬编码日期，一律用 `${bizdate}` 等调度参数注入，保证补数与重跑一致。

## 使用前必读（迁移到具体企业/平台时）

进入具体任务前，先向用户确认/读取以下事实，并把结论作为本次开发的上下文基线：

| 上下文项 | 说明 | 默认值（可被企业裁剪覆盖） |
|---|---|---|
| 目标平台 | MaxCompute / Hive / Spark SQL / 湖仓一体… | Hive/Spark SQL |
| 主目录/工作空间 | 按空间隔离的实际命名 | 见 `docs/01-architecture.md` 空间规划 |
| 业务域编码表 | 最终以企业登记为准 | `config/business_domains.md` |
| 来源系统编码表 | 最终以企业登记为准 | `config/source_systems.md` |
| 刷新周期 / 增量标识 | 编码取值 | `config/refresh_periods.md` |
| 系统简称 / 平台简称 | 命名占位取值来源 | `config/dialect.md` 附录 |

若企业有自建编码表，**优先覆盖本技能附带的参考编码**，不得强行套用参考值造成口径分歧。

## 标准工作流程

### A. 需求澄清（每次任务先对齐边界）
1. 明确本次目标：**建表 / 加工SQL / 集成 / 接口 / 质量 / 调度 / 验收 / 迁移** 中的哪一类。
2. 明确**分层落点**（ods / dwd / ads / srv / tmp / bak / dim / fct / dws）。
3. 明确**业务域、来源系统、刷新周期、数据粒度、敏感等级**。
4. 明确**目标平台方言**，按需查 `config/dialect.md` 做语法适配。

### B. 命名（先定名，再动手）
- 命名总则与模式占位符：见 `docs/02-naming.md`。
- 需要命名：表名、任务名、接口名、数据集名、文件交付名。
- 编码取值以 `config/` 为准，禁止自造词、禁止 `test/tmp/待定` 占位上线。

### C. 建模与建表
- 分层职责与三层目标：见 `docs/03-modeling.md`。
- 建表规范（表注释、字段注释、类型、分区、主键、etl_time、src_system/src_pk）。
- 直接套用 `templates/` 下的建表模板，替换业务字段。

### D. SQL 加工
- 通用书写规范、时间参数、增量策略、性能优化、反例：见 `docs/04-sql-dev.md`。
- **强制项**：覆盖写入保证幂等；WHERE 携带分区键；不用 `SELECT *`；业务日期用调度参数；禁止对分区列做函数包装；金额用 DECIMAL(18,4)。
- 增量、对账场景可复用 `templates/`。

### E. 数据集成（如需同步）
- 模式选型、任务命名、字段映射、水位管理、前后置语句：见 `docs/05-etl.md`。

### F. 数据服务（如需接口）
- 服务形态、接口设计、鉴权、分页限流、错误码：见 `docs/06-service.md`。
- 出参结构与示例见 `templates/interface_response.json`。

### G. 数据质量 / 调度 / 安全
- 质量维度、规则设计、对账、告警：见 `docs/07-quality.md`。
- 调度依赖、补数重跑、故障分级、巡检：见 `docs/08-scheduling.md`。
- 分级分类、权限、脱敏、审计：见 `docs/09-security.md`。

### H. 交付与验收
1. 按 `docs/12-acceptance.md` 的**验收检查表**（对应手册 13.2）逐项核对，任一项不通过即判定不通过。
2. 按 `checklists/review_checklist.md` 做代码评审。
3. 输出交付物清单（建表脚本 / SQL / 同步配置 / 接口定义 / 元数据登记 / 质量规则 / 调度配置）。

## 迁移到新平台的步骤（证明"可迁移"）
1. 在 `config/dialect.md` 增加一行目标平台方言列。
2. 全文检索正文中是否混入平台特有语法（约束一：日期函数、特殊表类型等）——若有，收敛回调度参数或抽到配置；约束二：确需平台特性时在任务注释显式标注依赖。
3. 复核 `templates/*.sql` 的建表/写入/分区语法是否被目标平台接受，必要时替换模板。
4. 用目标平台跑通一条端到端链路（ods→dwd→ads）验证。

## 扩展本技能的入口（证明"可扩展"）
- **新增业务域 / 来源系统 / 编码**：改 `config/` 下对应编码表，不需要动任何规范文档。
- **新增一个规范主题**：在 `docs/` 新增一个 `NN-主题.md`，并在 SKILL.md 的工作流对应位置挂一个引用即可。
- **新增一种平台方言**：`config/dialect.md` 增列。
- **新增一种表模板**：在 `templates/` 新增模板文件并在 C 步骤引用。
- **新增一个质量规则类型 / 告警**：`docs/07-quality.md` 的规则分类表中追加。

## 禁忌（不要做）
- 不用 `SELECT *` 作为生产输出；不遗留调试语句。
- 不用实时日期函数 / 硬编码日期替代调度参数。
- 不对分区列做函数包装（分区裁剪失效）。
- 金额不用 FLOAT/DOUBLE；丢失精度。
- 增量水位不硬编码，必须持久化（调度参数/元数据表）。
- 贴源层不加业务计算逻辑；共享层不面向单个报表裁剪。
- 不在 SQL 中散落魔法数字/字典码，用维表或常量参数。
- 接口错误信息不暴露 SQL、堆栈、表名等内部细节。
