# 10 开发流程与协作

## 环境规划
| 环境 | 用途 | 数据要求 | 访问控制 |
|---|---|---|---|
| 开发环境 | 日常开发、SQL 调试 | 脱敏样本或最小子集 | 项目组成员授权 |
| 测试环境 | 上线前集成验证、回归 | 结构与生产一致，数据可历史快照 | 项目组+测试 |
| 生产环境 | 正式调度、对外供数 | 生产真实数据，受分级分类管控 | 平台运维统一管理 |

> 禁止在生产环境直接调试；禁止将生产账号、连接串、密钥写入代码库、脚本注释或文档。

## 代码与版本管理
- 所有 SQL、建表语句、接口定义纳入版本库，与平台空间一一对应。
- 脚本按 **分层 / 目标表 / 任务名.sql** 组织，与平台任务名对应。
- 提交信息写明变更内容与关联需求单号，如 `[需求单号] 新增客户域日消费事实表`。
- 分支策略：`main`(生产可用) / `develop`(集成验证) / `feature/*`(特性开发)。
- 提交前执行格式与规范检查（命名、字段注释、分区、幂等性）。
- 禁止将含明文口令、个人信息的中间结果文件提交版本库。

## 发布流程
```
需求评审 → 编码提交 → 自测通过 → 规范检查 → 上线申请
→ 测试环境验证 → 生产发布 → 调度与依赖核对 → 首轮产出验证 → 交付运维
```
上线申请须附：需求单号与业务背景、影响范围说明、建表与变更脚本、自测记录与数据核对结果（行数/汇总值）、调度依赖与资源队列配置、异常回退方案。

## 评审要点
见 `checklists/review_checklist.md`（对应手册 11.4，13 项必检）。

## 文档要求
- 数据资产文档即元数据，不额外维护一套与表定义脱节的文档。
- 表注释含内容、粒度、来源、刷新频率；复杂口径在字段/任务注释说明。
- 指标字段口径与指标平台登记一致。
- 接口提供可调用的请求/返回示例。
- 重要表与核心口径补一页说明文档（背景、模型、边界、已知限制）。
