# 6 数据服务与接口开发

## 服务形态选型
| 形态 | 适用场景 | 优点 | 局限 |
|---|---|---|---|
| 数据 API | 实时/准实时按条件查询 | 灵活、权限细分 | 需治理接口数量与性能 |
| 结果数据集 | 固定口径周期性取数 | 实现简单、查询快 | 口径变更要重新发布 |
| 文件交付 | 跨组织离线交换 | 通用、链路简单 | 时效差、管理文件版本 |
| 消息推送 | 事件触发类场景 | 实时性好 | 可靠性与重放处理复杂 |

> 大批量导出不要走数据 API，应用数据集成下发结果表/文件，避免占用接口资源。

## 接口设计规范
| 要素 | 规则 | 示例 |
|---|---|---|
| 方法语义 | GET 查询、POST 写入/复杂查询、PUT 全量更新、DELETE 删除 | `GET /customer/profile` |
| 命名 | `{方法}_{业务对象}_{动作}_{口径}` | `get_customer_profile_by_org` |
| 路径 | `/{业务域}/{资源}/{动作}` | `/customer/profile/detail` |
| 版本 | 路径版本前缀或请求头版本号 | `/v1/customer/profile` |
| 入参命名 | 小写下划线；分页 `page_no`/`page_size`；时间 `start_time`/`end_time` | `page_size` |
| 出参结构 | 统一包裹 `code`、`message`、`data`、`total` | 见下 |
| 分页上限 | `page_size` 设最大值(建议1000)，超限截断并提示 | `page_size<=1000` |

出参结构与示例见 `templates/interface_response.json`。

## 鉴权与访问控制
- 服务到服务使用应用身份（appKey/appSecret、Token、mTLS），**不使用个人账号**。
- 消费方按"**应用 + 资源 + 操作 + 数据范围**"四维授权，最小必要原则。
- 限定网络来源（内网、专线、白名单）+ 应用鉴权双重控制。
- 密钥定期轮换，轮换期双密钥并存避免中断。
- 返回值按授权范围裁剪，禁止向低权限消费方返回敏感字段。

## 分页、排序与限流
- 分页参数统一命名并设上限；无入参/默认全量的接口**必须强制分页**。
- 排序字段必须是接口声明过的字段，禁止拼接任意排序列。
- 按消费方设置配额（QPS、日调用量），超限返回明确错误码而非静默截断。
- 导出类与查询类接口分开配额。

## 错误码与响应规范
| 错误码段 | 含义 | 示例 |
|---|---|---|
| 0 | 成功 | 0 |
| 100xx | 参数错误 | 10001 缺少必填参数 cust_id |
| 200xx | 业务错误 | 20001 客户不存在 |
| 300xx | 权限错误 | 30001 无数据访问权限 |
| 400xx | 限流与配额 | 40001 调用超出配额 |
| 500xx | 系统异常 | 50001 服务内部错误 |

> 错误信息不得包含 SQL、堆栈、表名等内部细节；须明确指出"哪里错了、怎么改"。

## 发布流程与版本管理
`接口定义评审 → 测试环境发布 → 联调与验证 → 消费方验收 → 生产发布 → 监控观察`
- 发布前必须测试通过；接口变更发新版本，旧版本保留过渡期并公告下线。
- 接口绑定稳定节点，避免依赖被删除。
- 上线后观察调用量、失败率、响应时长；变更同步更新接口文档与调用示例。
