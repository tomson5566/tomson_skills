# 3 数据建模与建表规范

## 建模方法与分层职责（勿混用）
| 分层 | 建模目标 | 典型手法 |
|---|---|---|
| 贴源层 | 忠实还原 | 1:1 映射源表，技术性清洗与类型对齐 |
| 共享层 | 业务主题化 | 按主题重构模型，统一编码与口径，保留必要历史快照 |
| 应用层 | 消费场景化 | 按场景组织宽表/结果表，围绕指标与报表需求 |

**硬约束**：贴源层不得引入业务计算逻辑；共享层不得面向单个报表裁剪；应用层不得重复实现共享层已沉淀的公共逻辑。

## 表结构规范
| 要素 | 要求 |
|---|---|
| 表名 | 符合 `docs/02-naming.md` |
| 表注释 | 必填：表内容、数据粒度、上游来源、刷新频率 |
| 字段名 | 小写字母+下划线，表达业务语义而非物理属性，禁止 SQL 保留字 |
| 字段类型 | 金额 `DECIMAL(18,4)`；比率 `DECIMAL(18,6)`；标识与编码 `STRING`；**金额禁止 FLOAT/DOUBLE** |
| 字段注释 | 必填，与字段名语义一致 |
| 主键 | 共享层及以上须明确逻辑主键或唯一性校验规则 |
| 空值 | 显式声明是否允许为空；默认值显式写出 |
| 分区字段 | 统一 `ds`（yyyyMMdd）；多租户另加 `tenant_id` |
| 字符集/时区 | 源端目标端一致，跨时区在字段级注明 |

## 分区与存储格式
- 分区字段固定 `ds`；业务时间与分区时间不同须在注释写明。
- 日分区超百 GB 考虑二级分区或拆表。
- 优先列式压缩格式（ORC / Parquet）。
- 控制输出文件数量与大小，治理小文件。
- 分区裁剪依赖分区列**裸过滤**，禁止对分区列做函数包装。

## 各层建表示例
- 贴源层：见 `templates/ods_table.sql`（保留 `etl_time` 判定同步水位）。
- 共享层三硬要求：字段名体现统一口径（如 `id_no`→`id_no_cipher`）；枚举统一映射企业字典；保留 `src_system` + `src_pk` 支持追溯。见 `templates/dwd_table.sql`。
- 应用层"可直接消费"：字段语义自解释、口径与指标平台一致、附统计日期与更新时间。见 `templates/ads_table.sql`。

## 维度建模实践
- **一致性维度**：同一业务维度全公司只保留一份定义，所有事实表引用同一张维度表（见 `templates/dim_table.sql`）。客户等级、渠道归属等高变更属性**退化**会产生事实表与维度不一致——退化维度**仅限低基数、极少变更属性**（城市、行业大类）。
- **事实表分类**：
  | 类型 | 特征 | 适用场景 | 注意 |
  |---|---|---|---|
  | 事务型事实 | 每行一次业务事件 | 订单、交易、工单 | 数据量最大，注意分区压缩 |
  | 周期快照 | 每行一个周期末状态 | 账户余额、库存 | 周期粒度与业务口径一致 |
  | 累积快照 | 每行一个周期累计状态 | 累计收入、累计欠费 | 与事务型易混淆，命名/注释须区分 |
