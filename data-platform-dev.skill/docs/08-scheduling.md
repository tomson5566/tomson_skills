# 8 调度与运维规范

## 调度模型
- 调度频率与源系统产出一致；默认日调度，非日调度在任务名/注释标注频次。
- 调度时间避开整点高峰，建议业务低峰。
- 依赖只建必要，禁止全链路串联。
- 大任务独立资源队列与并发上限；合理超时与重试（重试不得叠加写入）。
- 优先级按业务影响面设置，核心供数最高。
- 节假日/特殊日用调度日历控制，避免空跑。

## 依赖配置规范
| 情形 | 依赖方式 | 说明 |
|---|---|---|
| 仅用其他空间的表 | 依赖本空间根节点 | 不建跨空间强依赖 |
| 用本空间内的表 | 依赖对应上游节点 | 精确依赖保证时序 |
| 同步任务 | 依赖数据来源节点 | 采集完成再加工 |
| 跨空间取数 | 走数据服务/结果表授权 | 不直接跨空间依赖 |
| 多上游 | 全部完成才触发 | 设等待超时避免阻塞 |

> 依赖链深度建议 ≤ 5 层。过长时单点延迟放大为全局延迟，应合并中间任务或并行化。

## 补数与重跑
- 补数前确认影响范围（分区、上下游、消费方）并登记申请。
- 补数**从上游到下游逐层执行，严禁跳层**。
- 补数业务日期参数与原调度一致，**禁止用当前日期覆盖历史分区**。
- 覆盖写入补数后核对行数与关键指标汇总。
- 补数后更新受影响结果表与接口，通知消费方。
- 同一分区重复补数时确认幂等；非幂等先清理再补。

## 故障分级与响应
| 级别 | 判定标准 | 响应时限 | 恢复时限 | 通报范围 |
|---|---|---|---|---|
| P1 | 对外供数全面中断/核心结果表数据错误 | 30min | 4h | 数据平台+相关业务方 |
| P2 | 单批次失败，影响部分报表/接口 | 2h | 8h | 数据消费方 |
| P3 | 非关键任务失败/数据波动告警 | 4h | 24h | 运维台账 |

## 日常巡检清单
| 频率 | 巡检项 |
|---|---|
| 每日 | 前日批次成功率、失败任务、数据量波动告警、接口调用异常、存储增量趋势 |
| 每周 | 资源队列排队、长时任务、重复告警、慢查询 Top N |
| 每月 | 表生命周期与存储、血缘完整率、命名合规抽查、权限复核、成本趋势 |
| 每季度 | 模型与口径复核、消费方需求、废弃资产清理、容量规划 |

## 元数据与血缘
- 新表上线后完成元数据登记，确保可检索。
- 字段变更同步更新元数据，避免血缘脱节。
- 血缘覆盖表级与字段级；字段级血缘是影响面评估前提。
- 对外供数核心表标注消费方清单。
- **元数据缺失的表视为未交付资产，不进入生产调度。**
