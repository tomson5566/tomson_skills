# 1 架构总览与分层模型

## 核心概念
数据中台通过分层组织与统一服务，解决数据"散、乱、难用"。核心三件事：
- **统一接入**：把分散业务系统数据以统一方式汇聚，保持源数据可追溯。
- **统一口径**：把同一业务实体多源数据在共享层收敛为唯一标准模型，形成企业级事实。
- **统一服务**：把加工结果以数据集 / 接口 / 文件对外供给，避免消费方直接访问底层表。

## 分层模型与职责
| 分层 | 常用前缀 | 核心职责 | 能否被下游引用 | 典型加工内容 |
|---|---|---|---|---|
| 贴源层 | ods | 统一汇集源系统数据，保持源结构 | 否 | 抽取、字段映射、类型对齐、基础清洗 |
| 近源层 | buf(部分平台) | 周期性存储源系统增量数据 | 否 | 增量落盘、增量合并 |
| 共享层 | dwd | 落地业务主题明细与标准模型 | 是 | 覆模、编码统一、口径规范化、指标计算 |
| 数据服务区 | srv | 面向消费方的输出缓冲 | 是(受限) | 结果表发布、接口视图、数据集 |
| 应用层 | ads | 面向分析与场景的结果数据 | 是 | 维度建模、事实建模、汇总宽表、场景组装 |

依赖**单向**：应用层→共享层→贴源层/近源层，贴源层不依赖任何上层。

## 端到端数据链路
```
源业务系统 →采集/同步→ 贴源层 →清洗/映射/覆模→ 共享层 →场景加工→ 应用层
                                  ↕ 数据质量校验 / 血缘&元数据
               数据服务区 ←结果发布/数据集/接口-
                        ↓
          业务应用 · BI报表 · 风险模型 · 外部数据交换
```
开发工作定位 = 把"源系统的一张表"加工成"消费方可直接使用的可信数据"，每一步可追溯、可验证、可重跑。

## 空间与权限规划
| 空间类型 | 划分依据 | 用途 | 权限范围 |
|---|---|---|---|
| 接入空间 | 一个源系统一个空间 | 数据接入与清洗 | 仅接入组 |
| 整合空间 | 按业务域或系统族 | 模型建设与共享层加工 | 模型组 |
| 场景空间 | 按业务场景或应用 | 应用层加工与结果发布 | 场景组 |
| 公共空间 | 按主题域 | 公共维度、公共指标 | 全员只读 + 域管理员维护 |

> 跨空间访问应通过数据服务接口或结果表授权视图；不建议直接建立跨空间任务依赖。

## 命名元数据与生命周期（每张表创建时必备）
| 元数据项 | 必填 | 说明 |
|---|---|---|
| 中文表名 | 是 | 面向前业务人员的可读名称 |
| 业务域 | 是 | 归属主题域，用于目录组织与权限分组 |
| 数据粒度 | 是 | 一行代表什么（如"一行=一个客户的一天"） |
| 上游来源 | 是 | 直接上游表或源系统 |
| 更新频率 | 是 | 日/小时/周/月 |
| 责任人 | 是 | 业务侧与技术侧各一名 |
| 生命周期 | 是 | 保留时长，到期自动归档/清理 |
| 敏感等级 | 是 | 依据 `docs/09-security.md` 分级 |

## 分层生命周期建议
| 分层 | 建议生命周期 | 到期处理 |
|---|---|---|
| 贴源层 | 3—12 个月 | 归档后删除，必要时保留快照表 |
| 共享层 | 12—36 个月 | 按月分区滚动删除 |
| 应用层 | 通常 12—24 个月 | 历史分区归档 |
| 临时/中间表 | 7—30 天 | 任务结束自动清理 |
| 日志与中间结果表 | 7 天 | 自动清理 |
