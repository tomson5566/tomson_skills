# WOL 持久化配置

> 适用：WOL 配置一次容易，但**重启 / 网卡 link 重新协商后 wol 状态会重置为 `d`**。
> 本文讲怎么让它活下来。

## 1. 配置前的 capability 检查（必做）

```bash
ssh <host> 'ethtool <nic> | grep -E "Supports Wake-on|Wake-on"'
# 示例输出:
#   Supports Wake-on: pumbg   ← 能力集（支持的模式）
#   Wake-on: g                ← 当前状态（g = magic 已开）
```

**字母含义**（容易记错）：

| 字符 | 含义 | 备注 |
| --- | --- | --- |
| `p` | PHY activity | 网卡检测到 link 变化时唤醒 |
| `u` | unicast | 单播包唤醒（多数 switch 会拦截） |
| `m` | multicast | **多播**，**不是 magic** |
| `b` | broadcast | 广播包唤醒 |
| `g` | **magic packet** | **我们用的就是 `g`** |
| `d` | disabled | 当前未启用 |

> ⚠️ `m` 看起来像 magic 但其实是 multicast。magic packet 永远是 `g`。

**如果 capability 列表里没有 `g`**，比如只显示 `d`，先尝试 `ethtool -s <nic> wol g`，driver 拒绝（`Operation not supported`）就是真不支持，WOL 这条路堵了。

## 2. 持久化机制选择

| 系统 | 推荐机制 | 备选 |
| --- | --- | --- |
| Debian / Ubuntu / **Proxmox VE** (默认) | **ifupdown post-up hook** in `/etc/network/interfaces` | rc.local 兜底 |
| RHEL 9 / CentOS Stream / Fedora | NetworkManager dispatcher `/etc/NetworkManager/dispatcher.d/` | rc.local |
| 纯 systemd-networkd（不常见） | `/etc/systemd/network/<nic>.link` 的 `WakeOnLan=magic` | — |
| Alpine / OpenWrt | ifupdown 同 Debian | — |

**判断方法**：

```bash
test -f /etc/network/interfaces && echo "ifupdown"
systemctl is-active NetworkManager 2>/dev/null
systemctl is-active systemd-networkd
```

**Proxmox VE** 默认三样都有，但 PVE 用 ifupdown（`/etc/network/interfaces` 是真），systemd-networkd 在 PVE 上**不读 link 文件**。所以 PVE 一律走 ifupdown + rc.local 双钩子。

## 3. Debian / PVE（ifupdown）— 完整 recipe

```bash
# Step 1: 确认物理 slave 网卡名
ip -br addr show            # 看 IP 绑在哪个接口
bridge link show            # 看 vmbr0 的 slave

# Step 2: 确认能力
ethtool <phys_nic> | grep "Supports Wake-on"
# 必须含 'g'

# Step 3: 立即开启
ethtool -s <phys_nic> wol g

# Step 4: 验证
ethtool <phys_nic> | grep -E "Wake-on|Link detected"
# Wake-on: g   Link detected: yes

# Step 5: 持久化
cp /etc/network/interfaces /etc/network/interfaces.bak.$(date +%Y%m%d_%H%M%S)_pre-wol

# 在 iface <phys_nic> inet manual 段下加：
#   post-up /usr/sbin/ethtool -s <phys_nic> wol g
#   pre-down /usr/sbin/ethtool -s <phys_nic> wol g

# rc.local 兜底：
#   /usr/sbin/ethtool -s <phys_nic> wol g >/dev/null 2>&1 || true

chmod +x /etc/rc.local  # 如果文件刚创建
```

## 4. RHEL / Fedora（NetworkManager dispatcher）

```bash
# 创建 /etc/NetworkManager/dispatcher.d/99-wol-<nic>
#!/bin/bash
if [ "$1" = "<nic>" ] && [ "$2" = "up" ]; then
    /usr/sbin/ethtool -s "$1" wol g
fi
chmod +x /etc/NetworkManager/dispatcher.d/99-wol-<nic>
```

## 5. systemd-networkd link 文件（陷阱）

```ini
# /etc/systemd/network/10-enp7s0.link
[Match]
MACAddress=74:56:3c:49:9a:c4

[Link]
WakeOnLan=magic
```

**这个文件只在纯 systemd-networkd 环境有效。**

不生效的常见原因：
- **Proxmox VE 默认不读**（PVE 是 ifupdown + systemd 混合，networkd 没 enable）
- `MACAddress=` 写错
- `[Match]` 段没匹中

**不要在没确认 networkd 在用之前默认走这条路。**

## 6. 一键脚本

懒得手动操作？用 [scripts/install-wol.sh](../scripts/install-wol.sh)：

```bash
# 在目标机器上（必须 root）
bash install-wol.sh <nic>

# 例子
bash install-wol.sh enp7s0
bash install-wol.sh eth0
```

脚本会自动：
1. 检测系统类型（ifupdown / NetworkManager / systemd-networkd）
2. 立即开 wol g
3. 按系统类型加 hook
4. 备份原文件
5. 验证 `Wake-on: g` + `Link detected: yes`

## 7. PVE 重要补充

PVE 的 `/etc/network/interfaces` 文件头有：

```
# network interface settings; autogenerated
# PVE will preserve these directives, but will NOT read its network configuration from sourced files
```

意思是：**PVE 会自己改这个文件**。

- 手工段（`post-up ethtool`）放在 `iface` 块**内**会被保留
- 放外面或乱加 `auto unknown_iface` 会被 PVE 解析时跳过
- PVE Web UI 改网络会**重生成**文件，手工段需要重写
- 建议定期巡检 `grep -c ethtool /etc/network/interfaces`（应该 ≥ 1）

**详见 [pve-multi-nic.md](pve-multi-nic.md)。**

## 8. 真机验证的边界（重要）

`ethtool wol g` 配置成功 ≠ 真能唤醒。

要真唤醒，必须满足**全部**：

- 网卡 PHY 支持 magic（看 capability 字符串有 `g`）
- 网卡 link 物理在线（`Link detected: yes`）
- **BIOS 启用 Wake on LAN / Power on by PCIe**（很多主板默认关）
- 电源 AC 没掉
- 网卡所在交换机端口没被 disable / PoE 掉电
- 路由器 / VLAN 允许 directed broadcast（跨网段发包的话）

**没 BMC 的机器 poweroff 之前**，确认以上每一项，或者准备好物理显示器 + 键盘。
